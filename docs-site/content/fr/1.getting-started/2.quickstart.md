Ce guide met en place Dodock Wolf sur un bench : la Wolf App sur un site, le Wolf Agent sur
l'hôte, et une alerte par e-mail pour les pics de 502. Prévoyez un après-midi.

**Il vous faut :** un bench Frappe 15 ou Dokos (Dodock 5), Node 20.19 ou ultérieur pour
`bench build`, un accès root sur l'hôte, et un site qui hébergera les données de Wolf (il peut
s'agir d'un site existant).

::steps{level="3"}

### Installer la Wolf App

```bash [bench]
cd ~/frappe-bench
bench get-app https://github.com/bthuner/dodock-wolf
bench --site wolf.example.com install-app dodock_wolf
bench build --app dodock_wolf
```

L'installation crée les rôles **Wolf Manager** et **Wolf User**, un jeton d'enregistrement et les
[règles d'alerte prédéfinies](/fr/alerts/presets).

### Lancer le planificateur chaque minute

Wolf évalue les règles chaque minute, mais Frappe 15 et Dodock ont par défaut un tick toutes les
4 minutes.

```bash [bench]
bench set-config -g scheduler_tick_interval 60
# puis redémarrez le processus du planificateur du bench (supervisor ou systemd)
```

::warning
Sans ce réglage, une alerte peut arriver jusqu'à 4 minutes en retard, et « déclencher après
3 évaluations » signifie 12 minutes. La page **Monitoring** de la Wolf UI affiche le rythme en
vigueur.
::

### Installer l'agent sur l'hôte

Ouvrez **Wolf Settings → Agent install command** et copiez la commande en une ligne. Elle
ressemble à ceci :

```bash [hôte]
curl -fsSL https://raw.githubusercontent.com/bthuner/dodock-wolf/main/agent/install.sh \
  | sudo WOLF_URL=https://wolf.example.com WOLF_TOKEN=<registration token> bash
```

Le script installe l'agent dans `/opt/wolf-agent` (lié en `/usr/local/bin/wolf-agent`), crée un
utilisateur système `wolf-agent`, enregistre l'hôte, écrit `/etc/wolf-agent/config.json` et
démarre `wolf-agent.service`. Il trouve vos benches tout seul.

### Vérifier ce que voit l'agent

```bash [hôte]
sudo -u wolf-agent wolf-agent discover
sudo -u wolf-agent wolf-agent check --status
```

`discover` liste les benches, les sites et les chemins des logs. `check` collecte une fois et
affiche le JSON qu'il enverrait, sans l'envoyer. `--status` demande aussi au site son état de
santé.

### Ajouter un canal à une règle

Les règles prédéfinies ouvrent des incidents mais ne préviennent personne tant que vous n'avez pas
ajouté de canal. Ouvrez **Wolf Alert Rule → 502 spike after deployment**, ajoutez une ligne dans
**Channels** (type *Email*, votre adresse), enregistrez, puis cliquez sur **Send test
notification**.

Voir [Canaux](/fr/alerts/channels) pour Slack, Raven, PagerDuty et les autres types.

### Ouvrir la Wolf UI

Rendez-vous sur `https://wolf.example.com/wolf`. La vue d'ensemble liste les hôtes, les benches et
les sites avec leurs dernières métriques et leurs incidents ouverts. L'hôte apparaît dans la minute
qui suit le premier envoi.

::

## Marquer vos déploiements

Les règles comme *502 spike after deployment* ne se déclenchent que si un déploiement a touché le
même périmètre récemment. Les migrations de bench sur le site Wolf, ainsi que les tâches Press et
Pilot, sont enregistrées automatiquement. Pour les autres benches, ajoutez une ligne à votre script
de déploiement :

```bash [deploy.sh]
sudo -u wolf-agent wolf-agent mark-deployment --bench frappe-bench --note "v5.18.2" --silence 15m
```

La configuration qui contient le secret de l'agent n'est lisible que par `wolf-agent`, d'où le
`sudo -u`. `--silence 15m` ouvre aussi une
[fenêtre de maintenance](/fr/alerts/rules#fenêtres-de-maintenance) : les incidents continuent de
s'ouvrir pendant le déploiement, mais leurs notifications attendent qu'il se termine.
