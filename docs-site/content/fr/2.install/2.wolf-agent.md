Le Wolf Agent est un démon Python (3.9 ou ultérieur, bibliothèque standard uniquement). Installez-en
un par hôte : il surveille tous les benches de cet hôte.

## Installation en une ligne

Copiez la commande depuis **Wolf Settings → Agent install command**, ou écrivez-la vous-même :

```bash [hôte]
curl -fsSL https://raw.githubusercontent.com/bthuner/dodock-wolf/main/agent/install.sh \
  | sudo WOLF_URL=https://wolf.example.com WOLF_TOKEN=<registration token> bash
```

Depuis une copie locale du dépôt :

```bash [hôte]
sudo WOLF_URL=https://wolf.example.com WOLF_TOKEN=<registration token> ./agent/install.sh
```

Le script :

1. crée un venv dans `/opt/wolf-agent` et crée le lien `/usr/local/bin/wolf-agent` ;
2. crée l'utilisateur système `wolf-agent` et l'ajoute aux groupes `adm`, `systemd-journal` et
   `frappe` lorsqu'ils existent, pour qu'il lise les logs d'authentification, nginx et bench sans
   être root ;
3. enregistre l'hôte et écrit `/etc/wolf-agent/config.json` (mode 0600) ;
4. installe et démarre `wolf-agent.service` ;
5. sur un hôte [Frappe Pilot](/fr/install/pilot), installe `wolf-pilot-export`, une minuterie root
   qui copie les états des tâches et des processus du bench que l'agent ne peut pas lire lui-même.

## Options d'installation

| Variable | Effet |
|---|---|
| `WOLF_URL` | Le site Wolf central. |
| `WOLF_TOKEN` | Son jeton d'enregistrement (**Wolf Settings**). |
| `WOLF_BENCHES` | Chemins de benches séparés par des espaces, pour sauter la découverte automatique : `"/home/frappe/frappe-bench /srv/other-bench"`. |
| `WOLF_AGENT_SRC` | Source pip : un répertoire local ou une URL `git+https`. Par défaut : le répertoire du script, ou GitHub quand le script est lancé via curl. |
| `WOLF_AGENT_REF` | Référence Git pour une installation depuis GitHub. Par défaut `main`. |
| `WOLF_INSECURE=1` | Désactive la vérification TLS pendant l'enregistrement et les envois (site Wolf avec certificat auto-signé). |

Sans `WOLF_URL` ni `WOLF_TOKEN`, l'agent est installé mais pas enregistré. Enregistrez-le plus tard :

```bash [hôte]
sudo wolf-agent --config /etc/wolf-agent/config.json register --url https://wolf.example.com --token <token>
sudo chown wolf-agent: /etc/wolf-agent/config.json && sudo systemctl start wolf-agent
```

Sans systemd (dans un conteneur), le script affiche la commande à lancer en tant que `wolf-agent`.

## Découverte des benches

L'agent trouve les benches tout seul :

- un `bench.toml`, ou un répertoire qui contient `sites/` et `apps/frappe` ;
- les [benches Pilot](/fr/install/pilot), lus avec le vrai schéma `bench.toml` de Pilot ;
- les [serveurs Press](/fr/install/press), détectés à partir de `/home/frappe/agent/config.json`.

```bash [hôte]
sudo -u wolf-agent wolf-agent discover
```

## Vérification

```bash [hôte]
sudo -u wolf-agent wolf-agent doctor           # ce que l'hôte donne à l'agent, et ce qu'il faut corriger
sudo -u wolf-agent wolf-agent check            # collecte une fois, affiche la charge utile, n'envoie rien
sudo -u wolf-agent wolf-agent check --status   # demande aussi au site son état de santé
journalctl -u wolf-agent -f
```

L'hôte apparaît dans la Wolf UI en moins d'une minute. Sur le site Wolf, il correspond à un
enregistrement **Wolf Agent** (`WAG-0001`…) qui porte son nom d'hôte.

## Identifiants

Le secret de l'agent n'est affiché qu'une fois, à l'enregistrement. Le site n'en conserve qu'un
hash HMAC-SHA256 salé. Pour déplacer un agent ou récupérer une configuration perdue, cliquez sur
**Rotate secret** dans le formulaire **Wolf Agent**, ou enregistrez à nouveau l'hôte.

Si le site rejette les identifiants (401 ou 403), l'agent envoie une dernière alerte du
[chien de garde](/fr/agent/watchdog) et s'arrête avec le code de sortie 2, et systemd cesse de le
redémarrer.
