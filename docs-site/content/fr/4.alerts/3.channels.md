Chaque ligne du tableau **Canaux** (ou **Canaux d'escalade**) d'une règle est une destination.
Les secrets (jetons, clés, URL de webhook) sont des champs Password : stockés chiffrés, jamais
journalisés, et retirés de chaque erreur enregistrée.

**Envoyer une notification de test** sur le formulaire de la règle envoie un TEST à chaque ligne active et
affiche la réponse de chacune.

## Types

| Type | Envoie | Réglages |
|---|---|---|
| Email | un e-mail par destinataire, avec des liens signés Acknowledge / Resolve | Destinataires |
| Webhook | un JSON générique `{text, incident}` ([protocole](/fr/reference/protocol)) | URL Webhook |
| Raven | un message dans un canal Raven | Canal Raven |
| Slack | un message Block Kit avec une barre de couleur selon la gravité et des boutons Open / Acknowledge / Resolve | URL du webhook entrant\* |
| Mattermost | une pièce jointe de message avec couleur, champs et liens Acknowledge / Resolve | URL du webhook entrant\* |
| Matrix | un `m.room.message` avec un corps HTML | URL du serveur d'accueil, ID du salon, Jeton d'accès\* |
| ntfy | une notification push avec titre, priorité, tags, clic et boutons d'action | URL du serveur ntfy (ntfy.sh par défaut), Sujet, Jeton d'accès ntfy\* (optionnel) |
| Gotify | une notification push avec une priorité déduite de la gravité et une URL de clic | URL du serveur Gotify, Jeton d'application\* |
| SMS | un texte court (un ou deux SMS) via n'importe quelle passerelle HTTP | Numéros de téléphone, URL de la passerelle (modèle), Méthode HTTP, Format du corps, Modèle du corps, En-tête d'authentification, Secret\*, Longueur maximale |
| PagerDuty | Events API v2 : trigger, acknowledge, resolve ; `dedup_key` = nom de l'incident | Clé de routage\*, URL de l'Events API |

\* Champ Password : stocké chiffré, affiché sous forme d'astérisques.

## Qui reçoit quoi

- Les incidents ouverts et rouverts partent vers les **Canaux** ; les escalades vers les
  **Canaux d'escalade**.
- Quand quelqu'un acquitte ou résout un incident (dans Desk ou via un lien signé), les canaux
  **PagerDuty** reçoivent toujours l'événement `acknowledge` / `resolve` correspondant : l'alerte se
  ferme aussi côté astreinte.
- Les autres canaux ne sont informés d'une résolution que si la règle a **Notifier à la résolution** coché.
- Un test depuis le formulaire de la règle déclenche puis résout sur PagerDuty : il ne laisse donc
  jamais d'alerte ouverte.
- Pendant une [fenêtre de maintenance](/fr/alerts/rules#fenêtres-de-maintenance), les notifications
  attendent qu'elle se termine.

## Liens signés

Les alertes des incidents non résolus portent des liens signés **Acknowledge** / **Resolve**,
valables 24 h (**Wolf Settings → Durée des liens d'action (heures)**). Ouvrir un lien affiche une page de
confirmation ; seul son bouton agit, si bien que les scanners de messagerie ne peuvent pas acquitter
à votre place. Les incidents de sécurité portent aussi un lien par
[action de réponse](/fr/agent/response-actions) proposée par Wolf ; ces liens demandent la connexion
d'un Wolf Manager.

## Statut de livraison

Chaque tentative est enregistrée comme une **Wolf Delivery** : canal, cible sans les secrets, nature,
action PagerDuty, succès ou erreur, statut HTTP. L'incident les liste sous **Livraisons**. Les
livraisons suivent la rétention des événements.

## Mise à jour depuis la 0.1

Les récapitulatifs ont été retirés en 0.2 : chaque canal envoie chaque alerte immédiatement. Un
canal qui utilisait les récapitulatifs horaires en 0.1 reçoit désormais chaque alerte au moment où
elle se produit. Les récapitulatifs encore en attente lors de la mise à jour sont abandonnés, pas
envoyés : la mise à jour affiche leur nombre et l'enregistre dans un **Error Log** intitulé
*Dodock Wolf 0.2: pending digests dropped*. La version [v0.1.0](/fr/getting-started#rester-en-v010)
garde les récapitulatifs.

## Configuration par type

::collapsible{name="Slack"}
Créez une app → **Incoming Webhooks** → **Add New Webhook to Workspace**, et collez l'URL
`https://hooks.slack.com/services/…`. Les boutons ouvrent l'incident ou la page d'action signée :
aucun endpoint d'interactivité Slack n'est nécessaire. Slack peut afficher une icône d'avertissement
sur les boutons de lien des apps qui n'en ont pas.
::

::collapsible{name="Mattermost"}
**Integrations → Incoming Webhooks → Add**, puis collez l'URL `https://…/hooks/…`.
::

::collapsible{name="Matrix"}
Créez un compte bot, invitez-le dans le salon et faites-le rejoindre. Récupérez son jeton d'accès
(Element : **Settings → Help & About → Access Token**, ou `POST /_matrix/client/v3/login`). L'**ID du
salon** est l'identifiant interne `!…:server` (**Room settings → Advanced**), pas un alias. Les messages
sont envoyés avec `PUT /_matrix/client/v3/rooms/{room}/send/…`.
::

::collapsible{name="ntfy"}
N'importe quel topic sur ntfy.sh ou sur votre propre serveur. Sur un serveur public, choisissez un
topic impossible à deviner, ou protégez-le et collez un jeton d'accès (`tk_…`). Priorité : critical
5, warning 4, info 3, résolu 2 ; les escalades montent d'un cran.
::

::collapsible{name="Gotify"}
**Apps → Create application**, puis collez son jeton. Priorité : critical 8, warning 5, info 3,
résolu 2 ; les escalades montent de deux crans.
::

::collapsible{name="SMS"}
Indépendant du fournisseur. L'**URL de la passerelle** et le **Modèle du corps** optionnel acceptent les variables
`{to}`, `{text}` et `{secret}` : encodées en URL dans l'URL et dans les corps de formulaire,
échappées en JSON dans les corps JSON. L'**En-tête d'authentification** est une ligne d'en-tête comme
`Authorization: Bearer {secret}`. Mettez les clés d'API dans **Secret**, jamais dans l'URL. Une
requête par numéro de téléphone.

Le texte (nature, gravité, titre, périmètre, et l'URL de l'incident quand elle tient) est ramené à
l'alphabet GSM-7 et coupé sur une fin de mot à 160 caractères (un SMS) ou 306 (deux). Un texte qui
nécessite l'Unicode tient en 70 / 134.

```text [Une passerelle qui accepte du JSON]
Gateway URL:   https://sms.example.com/api/send
Method / Body: POST, json, {"to": "{to}", "message": "{text}"}
Auth Header:   Authorization: Bearer {secret}
```
::

::collapsible{name="PagerDuty"}
Ajoutez une intégration **Events API v2** à un service et collez sa clé d'intégration comme **Clé de
routage**. Modifiez l'**URL de l'Events API** pour la région UE (`https://events.eu.pagerduty.com/v2/enqueue`), ou
pour un récepteur compatible Events v2 : Grafana OnCall, Opsgenie et d'autres acceptent le même
corps.
::
