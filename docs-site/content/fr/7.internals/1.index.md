Dokos exploitera le sien, avec dokopilot, son fork de Pilot, dans les serveurs : c'est donc aussi la plateforme que Dokos devra faire tourner. La version illustrée est le [making-on](https://bthuner.github.io/dodock-wolf/making-on/).

## En un paragraphe

Frappe Cloud v2, ce sont six applications. **Central** est un site Frappe global unique : les équipes, la facturation, la console. Chaque région a un **Atlas** (un site Frappe qui fait tourner des machines virtuelles Firecracker sur des hôtes physiques, avec un proxy devant) et un **Cargo** (un site Frappe qui construit les images, fait tourner le stockage S3 et fait tourner le magasin de télémétrie de la région). **Datum** est l'API d'écriture de ce magasin, devant ClickHouse. **Beacon** est un site Frappe global unique qui lit le ClickHouse de chaque région et appelle l'astreinte. Un serveur client est une machine virtuelle qui fait tourner **Pilot**, lequel gère le bench et ses sites. Les applications ne partagent jamais de base de données : elles se parlent en HTTPS, avec des jetons Ed25519 de courte durée, des webhooks signés par HMAC et le service de métadonnées de la machine virtuelle.

## Trois plans

| Plan | Combien | Applications | Possède |
|---|---|---|---|
| Global | un site chacune | Central, Beacon | Les équipes, les capacités, la facturation, la console ; les incidents, les niveaux de service, les appels d'astreinte, la page de statut |
| Région | un de chaque par région | Atlas, Cargo, Datum + ClickHouse, le proxy, la passerelle WireGuard, Garage (S3) | Les hôtes et les machines virtuelles, les réseaux, les routes et le certificat générique (wildcard) ; les images, les buckets ; la télémétrie |
| Serveur | une machine virtuelle par serveur client | Pilot, le bench, les sites, MariaDB, Redis, nginx | Les applications, les sites, les sauvegardes, les mises à jour, les certificats des domaines personnalisés, tous les journaux |

## Qui possède quoi

| Question | Propriétaire | Pas |
|---|---|---|
| Qui est cette équipe, et cette personne a-t-elle le droit de faire cela ? | Central (`Team`, 18 capacités) | Les régions ne voient qu'un numéro de locataire |
| Ce serveur existe-t-il, et tourne-t-il ? | Atlas (`Virtual Machine`), reflété dans Central | Pilot |
| Quels sites et quelles applications ce serveur a-t-il ? | Pilot (`bench.toml`, des fichiers) | Central n'a ni DocType Bench ni enregistrement de déploiement |
| Où va ce nom d'hôte ? | Central décide (`Site Domain`), le proxy de la région applique | Le site d'Atlas n'est pas sur le chemin |
| Qui détient le certificat de ce site ? | Le proxy pour les noms génériques de la région ; le serveur pour un domaine personnalisé | Central |
| Qu'a mesuré ce serveur ? | Le ClickHouse de Datum, par région | Central |
| Quelque chose ne va-t-il pas sur la plateforme ? | Beacon | Un seul site ou un seul serveur en échec : Pilot prévient son propriétaire par Central |
| Que s'est-il passé à l'intérieur du bench ? | Personne en dehors du serveur | Voir [Dans un serveur client](/fr/internals/customer-server) |
