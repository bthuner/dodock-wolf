Avant qu'un événement soit placé dans la file locale ou envoyé, l'agent nettoie son titre et chaque
chaîne de sa charge utile : lignes d'exemple, tracebacks, messages, routes. Ce nettoyage (scrubbing)
est actif par défaut.

| Quoi | Devient |
|---|---|
| adresses e-mail, y compris encodées en URL (`jane%40example.com`) | `[EMAIL]` |
| valeurs des en-têtes `Authorization:` / `Proxy-Authorization:`, valeurs de `Cookie:` / `Set-Cookie:` | `[REDACTED]` |
| identifiants `Bearer …`, `token <key>:<secret>`, `Basic …` | `[REDACTED]` |
| JWT (`eyJ….….…`) | `[JWT]` |
| valeurs de `password`, `pwd`, `new_password`, `*_secret`, `*_token`, `api_key`, `sid`, `session_id`, `otp`, `signature`, dans les query strings, les formulaires, le JSON ou les représentations de dict Python | `[REDACTED]` |
| nombres qui ressemblent à des numéros de carte (13 à 19 chiffres, clé de Luhn valide, chiffre d'émetteur de 2 à 6) | `[CARD]` |
| chaînes qui ressemblent à des IBAN (contrôle mod-97) | `[IBAN]` |
| adresses IP, uniquement avec `"ips": true` | `[IP:<8 hex>]`, un hash à clé, stable pour un même agent |

## Adresses IP

Les IP sont conservées par défaut, car les règles de force brute SSH et de « connexion admin depuis
une nouvelle IP » reposent sur elles. Activez `ips` si les adresses sont pour vous des données
personnelles et que vous pouvez vous passer du regroupement par IP dans les titres.

## Ce qui ne change jamais

Le type, l'hôte, le bench, le site, l'horodatage et l'empreinte (fingerprint). Les empreintes sont
calculées sur les lignes brutes avant le nettoyage : le regroupement et la déduplication sur le site
Wolf fonctionnent donc de la même façon dans les deux cas.

Les métriques ne contiennent aucun texte libre et ne sont pas nettoyées. Le texte que vous saisissez
vous-même (`mark-deployment --note`) est envoyé tel quel.

## Réglages

```json [/etc/wolf-agent/config.json]
"scrub": {
  "enabled": true,
  "ips": false,
  "extra_patterns": [
    "internal-\\d{4}",
    {"pattern": "CUST-\\d{6}", "replacement": "[CUSTOMER]"}
  ],
  "keep": ["@dokos.io", "noreply@example.com"]
}
```

::field-group
  :::field{name="extra_patterns" type="array"}
  Des regex supplémentaires : une chaîne (remplacée par `[REDACTED]`) ou
  `{"pattern", "replacement"}`. Les regex invalides sont journalisées et ignorées.
  :::

  :::field{name="keep" type="array"}
  Valeurs jamais remplacées : chaînes exactes (sans tenir compte de la casse), ou `@domain` pour
  conserver toutes les adresses de ce domaine, comme vos propres e-mails système.
  :::

  :::field{name="enabled" type="boolean"}
  `"scrub": false` ou `"enabled": false` envoie les lignes telles quelles.
  :::
::

Lancez `wolf-agent check` pour voir exactement ce qui serait envoyé.
