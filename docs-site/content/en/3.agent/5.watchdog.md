Wolf alerts are sent by the Wolf site. When that site, its database or its scheduler is down,
nobody would hear about it. So the agent watches the site and alerts through its own **fallback
channel**, which does not go through the site.

## When it alerts

Every push response carries the site's `health` ([protocol](/reference/protocol)). The agent raises
an outage when:

- pushes have failed for `stale_minutes`: the site, a proxy or the database is down;
- the site reports its alert rules (or, with no rule enabled, its scheduled jobs) have not run for
  `stale_minutes`: scheduler stopped or paused, no worker, Redis down, or stored times pushed into
  the future by a time-zone change;
- queued pushes have waited `stale_minutes` for a worker. In `async` ingest mode, the site answers
  before storing, so pushes look fine while nothing is stored.

It sends one alert per outage, then one recovery notice when pushes work and rules run again. The
state is kept in `<spool_dir>/watchdog-state.json`, so a restart neither repeats the alert nor
forgets the outage. A failed delivery is retried every minute.

If the site rejects the agent's credentials, a last alert goes out before the agent exits.

## Channels

Both are optional. When both are set, both are used.

```json [/etc/wolf-agent/config.json]
"watchdog": {
  "enabled": true,
  "stale_minutes": 5,
  "webhook_url": "https://chat.example.com/hooks/xxxx",
  "smtp": {"host": "smtp.example.com", "port": 587, "starttls": true,
           "from": "wolf@example.com", "to": ["ops@example.com"],
           "user": "wolf", "password": "…"}
}
```

::field-group
  :::field{name="webhook_url" type="string"}
  POSTs `{"text": "..."}`, which Slack, Mattermost and Rocket.Chat incoming webhooks accept.
  :::

  :::field{name="smtp" type="object"}
  `host`, `port` (default 25; 587 with `starttls`, 465 with `ssl`), `from`, `to` (list or
  comma-separated), `starttls` (default on for port 587), `ssl`, `user`, `password`, `verify_tls`.
  :::

  :::field{name="stale_minutes" type="number"}
  Default `5`.
  :::
::

With no channel, the watchdog only logs to the journal at ERROR level. `"enabled": false` turns it
off.

```bash [host]
sudo -u wolf-agent wolf-agent test-fallback   # after editing the config
sudo -u wolf-agent wolf-agent check           # shows the watchdog state on stderr
```

::tip
Point the fallback at a channel that does not depend on the Wolf site's host: another mail relay,
or a chat webhook.
::

## On the timeline afterwards

While its rules are stale, the site records a `scheduler_stalled` event on each push. The
**Scheduler stalled** preset turns it into an incident once the scheduler runs again, so the outage
appears on the Wolf timeline.
