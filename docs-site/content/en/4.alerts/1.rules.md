A **Wolf Alert Rule** reads a window of metrics or events every minute. When its condition holds, it
opens one incident per group and notifies its channels.

## Fields

| Field | Meaning |
|---|---|
| **Signal Type** | `metric`: aggregate metric samples (or their rollups for windows over 3 h, see [Metric storage](/reference/metric-storage)). `event`: count Wolf Events. |
| **Metric Name** / **Event Type**, **Event Category**, **Min Severity** | What to read. For example `http_502`, or `security` / `web_attack_probe`. |
| **Aggregation** | `avg`, `min`, `max`, `sum`, `count`, `last`. Use `min` for "stayed above for Z minutes" and `sum` for counters such as `http_5xx`. |
| **Operator**, **Threshold** | `>`, `>=`, `<`, `<=`, `==`, `!=` against a number. |
| **Window Minutes** | The look-back. Default 5. |
| **Min Samples** | Fewer samples in the window than this, and the rule does not breach. |
| **Group By** | `host`, `bench`, `site`, `host_label` (for example per disk mount) or `none`. One incident per group. |
| **Filter Host / Bench / Site** | Limit the rule to one scope. |
| **Active From / To** | Only evaluate in this window. It may wrap midnight (`04:00 → 01:00`). |
| **Require Recent Deployment** | Only fire if a deployment hit the same bench, site or host in the last **Deployment Window Minutes** (30). |
| **Fire / Resolve After Evaluations** | Consecutive breached (or clear) evaluations, one per scheduler tick, before an incident opens (or auto-resolves). Default 1. |
| **Separate Resolve Threshold** | Hysteresis: fire above 90, resolve only once at or below 80. |
| **Cooldown Minutes** | Re-fire into the just-resolved incident instead of opening a new one. An event rule reopens it only for an event newer than the resolution; a metric rule, while its window still breaches. Default 30. |
| **Auto Resolve** | Resolve the incident when the condition clears. Default on. |
| **Channels** | Where alerts go. See [Channels](/alerts/channels). |
| **Notify On Resolve** | Also tell the channels when the incident resolves, automatically or by hand. Default on. PagerDuty always hears it. |
| **Escalate After Minutes**, **Escalation Channels** | If still `Open` (not acknowledged) this long after the first alert, notify the escalation channels once. |
| **Severity** | Of the incident: `info`, `warning`, `critical`. |

The rule form shows **Last Evaluated**, **Last Fired** and **Last Error**.

## Maintenance windows

A **Wolf Silence** (host, bench, site and/or rule, **Starts At**, **Ends At**) keeps incidents
opening, so the timeline stays complete, but holds back their notifications. Incidents still open
when the window ends are notified then.

Create one:

- in Desk (**Wolf Silence → New**);
- through the REST API: `POST /api/resource/Wolf Silence`;
- with the deployment marker: `wolf-agent mark-deployment --bench main --silence 15m`.

## Digests

Each channel row can use an **hourly digest**: `info` and `warning` alerts are batched into one
message per destination. `critical` alerts are always sent at once, and PagerDuty is never
digested.

## Test a rule

**Send test notification** on the rule form sends a TEST to every enabled channel row and shows
what each one answered.
