Wolf Agent

Commandes

La ligne de commande wolf-agent.

Lancez les commandes en tant qu'utilisateur wolf-agent, propriétaire de la configuration : sudo -u wolf-agent wolf-agent <command>.

Options globales : --config PATH (ou $WOLF_AGENT_CONFIG), -v.

CommandeRôle
register --url URL --token TOKEN [--bench PATH]...Enregistre l'hôte, découvre les benches, écrit la configuration.
runLa boucle du démon. C'est ce que lance systemd.
refreshEn root : relit ce que l'utilisateur de l'agent ne peut pas lire (le dossier des benches et le proxy d'un serveur Press ; le log d'accès d'un proxy Press) et l'enregistre dans la configuration, sans nouvel enregistrement. install.sh la lance à chaque mise à jour.
discover [--bench PATH] [--platform auto|press|generic]Affiche ce que trouve la découverte des benches.
check [--from-start] [--status] [--platform …]Collecte une fois et affiche la charge utile JSON. Rien n'est envoyé. L'état du chien de garde part sur stderr. --status demande aussi au site son état de santé.
doctor [--json] [--offline]Vérifie ce que l'hôte donne à l'agent et ce qu'il faut corriger : l'enregistrement et le site Wolf, chaque log, bench, Redis de file d'attente et log nginx, la base des jobs Press ou l'export Pilot, le log d'authentification ou le journal, les actions de réponse, le démon. Lecture seule. Sort avec le code 1 quand une vérification échoue. Voir Vérifier un hôte.
mark-deployment --bench NAME [--site S] [--note TEXT] [--silence 15m]Place un marqueur de déploiement sur la chronologie Wolf. --silence ouvre aussi une fenêtre de maintenance qui coupe les notifications pour ce bench ou ce site.
test-fallbackEnvoie un message de test via les canaux de secours du chien de garde.
demo press|multi|single [--root DIR] [--days N] [--no-live] [--cycle MIN] [--configure]Écrit un serveur simulé que cet agent lit : des jours d'historique, puis du trafic et des incidents en direct. Pour les démos et les tests uniquement.

Marquer un déploiement

deploy.sh
sudo -u wolf-agent wolf-agent mark-deployment --bench frappe-bench --site erp.example.com \
  --note "ERPNext v15.42 + custom app 2.3" --silence 15m

Le marqueur est un événement deployment. Les règles avec Require recent deployment ne se déclenchent qu'après un déploiement, et les incidents sont liés au dernier déploiement de leur périmètre. Le texte passé avec --note est envoyé tel quel, sans nettoyage.

Les tâches Press et Pilot, ainsi que bench migrate sur les sites qui exécutent la Wolf App, sont marquées automatiquement.

Lancer une démo

demo KIND dispose un serveur simulé sous --root (par défaut /home/frappe/demo-KIND). Les sites ne sont que des noms : rien ne tourne derrière.

TypeServeurDéploiements
pressun serveur d'applications Press : 3 benches, 8 sites (dont deux avec un domaine personnalisé), le jobs.sqlite3 de l'agent Press, nginx au format de Presstâches Press, lues par l'agent
multides benches classiques : 2 benches, 6 sites (dont deux avec un domaine personnalisé), un journal nginx commençant par $hostmarqués via le point d'entrée des déploiements, comme le fait mark-deployment
singleun bench, un sitecomme multi

Chaque type a aussi un auth.log. Utilisez un hôte ou un conteneur dédié, enregistré sous un nom à lui :

hôte de démo
wolf-agent register --url https://wolf.example.com --token TOKEN --hostname dokos-multi-1 --bench /home/frappe/demo-multi
wolf-agent demo multi --configure   # pointe l'agent sur la démo, contrôles sans rien derrière coupés
wolf-agent run &                    # l'agent d'abord : il doit ouvrir les fichiers quand ils sont vides
wolf-agent demo multi               # 7 jours d'historique, puis un cycle d'incidents toutes les 30 minutes

--bench désigne un dossier qui n'est pas encore un bench : l'hôte s'enregistre sans bench, et ceux de la démo arrivent dans Wolf avec sa télémétrie. Pour press, ajoutez --platform press.

La démo attend que l'agent suive chaque fichier, puis écrit l'historique, qui arrive dans Wolf par la découverte, les lecteurs de journaux et les parseurs de l'agent. Les métriques d'hôte passées, que l'agent mesure en direct, passent par sa file d'attente sur disque. Chaque cycle comprend un déploiement suivi de 4 minutes de 502, une trace d'erreur de requête, une tâche planifiée en échec, un worker tué, une attaque SSH par force brute (une sur trois réussit), un balayage d'attaque web et, un cycle sur deux, une opération de bench en échec (une tâche Press Patch App, ou une trace d'erreur de bench update).

Les règles regardent les dernières minutes : les incidents s'ouvrent pour les cycles en direct, pas pour l'historique. bench --site SITE generate-demo-press (ou -multi, -single) avec --agent-config PATH fait la même chose depuis un bench où l'agent est installé, et --webhook URL y envoie aussi les alertes de la démo. La page Développement lance le tout dans Docker.

Vérifier un hôte

hôte
sudo -u wolf-agent wolf-agent doctor

Lancez-la avec l'utilisateur de l'agent : root lit ce que le démon ne peut pas lire, et masquerait des problèmes. Chaque ligne vaut ok, WARN, FAIL ou -- (pour information), avec la correction après un avertissement ou un échec :

logs
  ok   18 log file(s) readable
  --   9 not written yet (read once they appear): bench-1/frappe.web.log ...

platform
 FAIL  Press: /home/frappe/agent/jobs.sqlite3-wal is not the Press agent's: its jobs fail to write
        fix: stop the Press agent (supervisorctl stop 'agent:'), delete ...-wal and -shm, start it

Elle vérifie les fichiers que le démon suivrait et les benches à partir desquels il travaille (sur Press, ceux qu'il redécouvre), pas seulement la configuration. --json affiche les vérifications sous forme de liste, --offline n'appelle pas le site Wolf. Rien n'est écrit, et le code de sortie vaut 1 quand une vérification échoue, ce qui permet d'en faire une étape d'un script d'installation.

Le démon lance les mêmes vérifications toutes les heures (setup_checks) et les envoie avec un push : la page Monitoring de la Wolf UI affiche la configuration de chaque hôte, ses problèmes et leurs corrections, et la règle prédéfinie Host setup problem ouvre un incident tant qu'une vérification échoue.

Voir la charge utile

hôte
sudo -u wolf-agent wolf-agent check --from-start | jq '.events[] | {type, category, title}'

--from-start lit les journaux depuis le début au lieu des positions enregistrées, ce qui sert à tester un parseur sur un fichier existant. check n'envoie jamais rien et ne déplace jamais les positions.
